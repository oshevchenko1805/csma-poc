# Специфікації рисунків розділу 4 — до побудови

Розділ 4 будується за пʼятьма security properties. Нумерація рисунків
відповідає порядку появи в тексті, а не порядку створення.

Правило для кожного рисунка: **одне питання, одна відповідь, яку читач
дістає за пʼять секунд**. Якщо рисунок вимагає абзацу пояснень до того,
як стане зрозумілим, він не працює.

---

## 4.1 Свип по втратах каналу

**Секція:** Detection capability, межа застосовності.

**Питання, на яке відповідає:** чи тримається перевага меша на
ідеальному каналі? Це перше заперечення, яке поставить рецензент.

**Дані:** `runs_final/detection_vs_loss.csv`, 10 рівнів втрат, 255
валідних прогонів.

**Форма:** одна панель, лінійні осі.
x = ймовірність втрати пакета меша, 0 … 0.65.
y = частка виявлення, 0 … 1.
Крива C з інтервалами Вілсона; горизонтальна лінія A і B ≈ 0 біля осі.
Підписи n над точками.

```
1.0 |  o--o
    |       \o
0.5 |          o--o--o--o
    |                      o
0.0 |__A,B_____________________o___
     0        0.3        0.6
```

**Що читач має винести:** деградація плавна, плато на 0.46, у нуль не
падає навіть при втратах 0.65. Меш не «ламається», він втрачає чутливість.

**Ризик:** останні дві точки мають n=12, інтервали широкі. Не
екстраполювати; підписати n біля кожної точки.

**Статус:** ГОТОВО — `figures/fig4_1_losssweep`. Перенумеровано і
перенумерація.

## 4.2 Плато правила підтвердження k

**Секція:** Detection capability, захист вибору параметра.

**Питання:** чи не підібрано `sustained_samples = 3` під результат?

**Дані:** `metrics/sustain.py`, перерахунок офлайн із збережених рядів
`pos_horiz_ratio`; 45 прогонів gps_spoofing, 90 чистих.

**Форма:** дві панелі одна під одною, спільна вісь x = k, 1 … 6.
Верхня: частка виявлення. Нижня: частка чистих прогонів із хибним
спрацюванням. Робоча точка k=3 позначена вертикаллю, плато k=2…4
затінене.

**Що читач має винести:** вибір лежить на плато, з обох боків від нього
гірше. k=1 повертає пропущену атаку, але вчетверо збільшує хибні тривоги.

**Ризик:** дві шкали. Не робити подвійну вісь — уже пробували, точка
перетину читається як подія і не значить нічого. Панелі лишити
роздільними.

**Статус:** ГОТОВО — `figures/fig4_2_sustain`. Перенумеровано, приведено до спільної палітри, вікна названо явно в підписі.

## 4.3 Треки апарата: A проти C

**Секція:** Recovery capability, механізм.

**Питання:** що фізично робить відновлення? Жодна таблиця цього не
показує.

**Дані:** `trajectory.jsonl`, ґрунтова істина Gazebo, ~5 Гц. Потрібно
витягти з VM. Прогони обрані як медіанні у своїх комірках:

| панель | прогін | відхилення |
|---|---|---|
| A, gps_spoofing | `A_gps_spoofing_r4_1785562555` | 49.84 м |
| C, gps_spoofing | `C_gps_spoofing_r3_1785309732` | 19.68 м |
| C, command_injection | `C_command_injection_r1_1785395502` | 0.41 м |

**Форма:** три панелі в ряд, однакові осі north/east у метрах.
Місійний маршрут — тонка сіра замкнена лінія.
Трек атакованого апарата — чорна суцільна; треки двох інших — світло-сірі.
Момент інʼєкції — порожній кружок; момент виявлення — заповнений;
момент стабілізації — хрестик.

```
   A / gps            C / gps           C / injection
  ___________        ___________        ___________
 |  ....     |      |  ....     |      |  ....     |
 |  :  o--->>|      |  :  o->x  |      |  :  ox    |
 |  :........|      |  :........|      |  :........|
 |___________|      |___________|      |___________|
   зійшов на 50 м     зупинився         не зійшов
                      на 19.7 м
```

**Що читач має винести:** у A трек іде геть від маршруту і не
повертається; у C він зупиняється там, де його застало виявлення; при
інʼєкції C взагалі лишається на маршруті. Три різні поведінки, нуль
статистики.

**Друга функція цієї панелі:** видно, звідки береться фазове
розходження. Два світло-сірі треки продовжують маршрут, чорний стоїть —
ось і 145 м відставання. Це знімає підозру, що 145 м у рис. 4.4 є
поразкою.

**Ризик:** треки треба будувати в тій самій системі координат, що й
місійний план (ENU, gz.x = схід, gz.y = північ — підтверджено на 4383
вибірках). Помилка тут зіпсує все.

**Статус:** ГОТОВО — `figures/fig4_3_tracks`, `metrics/plots_tracks.py`. Дані з VM лежать у `figdata/`, три прогони закомічені.

## 4.4 Розмен: стримування × координація

**Секція:** Mission resilience і Coordination integrity, спільно.

**Питання:** скільки коштує стримування?

**Дані:** `campaign_master.csv`, поля `mission_degradation_m` і
`phase_excess_m`, валідні прогони чотирьох сценаріїв.

**Форма:** скаттер, лінійні осі, одна точка = один прогін.
x = відхилення від місії, м, 0 … 55.
y = фазове розходження, м, 0 … 190.
Маркери за архітектурою (o / s / ^), підпис біля кожного кластера —
сценарій.

**Дві речі, без яких рисунок бреше:**

1. **Вертикаль на 49.8 м** із підписом «стеля інжекції». Кластер A і B
   стоїть саме на ній, і без цієї лінії рисунок стверджує, що вони
   деградували рівно на 49.8 м, тоді як вони просто вперлись.
2. **Підписані кути**, а не «низ добре, верх погано»:
   лівий нижній — «обидві цілі досягнуто»;
   правий — «маршрут втрачено»;
   верхній — «строй втрачено».

```
 190 |        C dt-gps o
     |        C gps  o          <- строй втрачено
     |
 100 |    comm (A,B,C разом)
     |                          <- обидві втрачені
  15 |                        A,B gps ||
     | C injection              A,B inj|| стеля
   0 |_o______________________________||____
     0        20         40        49.8
       обидві цілі            маршрут втрачено
       досягнуто
```

**Що читач має винести:** C переміщується вліво і вгору — стримування
куплене строєм. При інʼєкції C переміщується в початок координат — інший
режим, виграш за обома осями. A і B стоять біля стелі й нікуди не
рухаються.

**Чому comm_disruption лишити на рисунку:** усі три архітектури лягають
в одну точку високо по y. Це доводить, що високе фазове розходження буває
й без будь-якої дії архітектури, і знімає читання «C ламає координацію».

**Ризик, головний:** без підписаних кутів рисунок відтворює провал
раунду 1 — A і B опиняються в «хорошій» нижній зоні. Це та сама пастка,
на якій рисунок прочитався навпаки.

**Статус:** ГОТОВО — `figures/fig4_4_tradeoff`, `metrics/plots_tradeoff.py`.

## 4.5 Карта режимів 5 × 3

**Секція:** синтез, кінець розділу 4 або початок розділу 5. **Не
всередині окремої властивості** — вона перетинає всі пʼять.

**Питання:** як усі пʼятнадцять комірок складаються в одне твердження?

**Форма:** матриця 5 атак × 3 архітектури, у комірці порядковий клас
ісходу 0…4 плюс три підтверджувальні числа. Дужки режимів праворуч.

**Що читач має винести:** повторювані комірки складаються в блоки, і
видно чотири режими. Це виміряний двійник табл. 3.10.

**Дві умови, без яких вона вразлива:**

1. схему з пʼяти класів **оголосити в розділі 4 як методологію, до
   показу результатів**;
2. додати перевірку стійкості — чи змінюється картина при порозі 10 і
   20 м замість 15. Один абзац, без окремого рисунка.

**Статус:** ГОТОВО — `figures/fig4_5_regimes`, `metrics/plots_regime.py`.
Перенумерувати на 4.5.

## Стан набору

**Усі пʼять побудовані.** Одна команда перезбирає весь набір з нуля:

```bash
python -m metrics.figures_ch4
```

Вона й тільки вона визначає, що входить у набір розділу 4. Старий набір
`fig1..fig9` вилучено з `figures/`; код тих рисунків лишився в
`metrics/plots.py` і `metrics/plots_extra.py`, але з `main()` набору не
викликається.

### Нумерація: одне джерело

Розбіжність, знята 4 серпня. `CH45_QUESTIONS_ANSWERS_FIGURES.md` §4
подавав інший порядок (карта режимів як 4.1, свип як 4.4). Два рисунки
встигли зберегтися під різними схемами: `fig1_regimes` за однією,
`fig44_tradeoff` за іншою.

**Чинна нумерація — ця сторінка.** Вона лягає на структуру розділу за
пʼятьма security properties: Q1 detection дає 4.1 і 4.2, Q3 recovery
дає 4.3, Q4 і Q5 разом дають 4.4, синтез дає 4.5. Порядок із
`CH45_QUESTIONS_ANSWERS_FIGURES.md` вважається застарілим; ставити
карту режимів першою суперечило б власній вимозі оголосити схему пʼяти
класів як методологію ДО показу результатів.

### Що лишилося зробити по 4.5

Перевірка стійкості порогів: чи змінюється картина при 10 і 20 м
замість 15. Один абзац у тексті, окремого рисунка не потрібно.
